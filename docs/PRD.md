版本 v1.1 | 产品经理：许清楚 | 状态：已对齐架构 Spec（ARCHITECTURE.md v1.0）

v1.1 变更：按架构边界移除「实时协同、评论与 @ 提及、AI 问答、PDF 导出」的 MVP 承诺；澄清编辑器形态与字面检索；修订附件上限 50MB、主题四套、版本生成时机；新增第九节回应架构侧三个决策提问。

## 一、一句话描述

一套可私有化部署在内网服务器上的企业文档 Wiki 知识库，用 AD 域账号即登录、按域用户组自动收敛可见范围、用中文分词搜索找得到，且运行时不依赖任何外网服务。

## 二、目标用户与核心问题

**目标用户**：50 至 2000 人规模、已部署 Windows AD 域、有内网服务器、文档涉及内部制度与技术资产的中国企业。

**核心问题（三个，按严重度排序）**：

1. **搜不到**。制度文档散落在个人电脑、共享盘、微信群文件里；即便搬进现有工具，PostgreSQL 默认英文分词导致搜"年假"搜不到含"年假"的文档（Outline 已知高频缺陷），Confluence 搜索只索引 6 种附件格式且相关度受页面标签习惯影响极大。
2. **权限失控**。员工离职后权限滞留、组织调整后需人工重配；根源是 AD/LDAP 的身份生命周期与文档访问控制面未解耦。同时 Confluence 的七八层权限配置对 50 人公司过重，开源 wiki（BookStack / Wiki.js / DokuWiki）又缺少"部门/团队"概念，AD 组到内部角色的映射要二次开发。
3. **不能落地内网**。语雀是纯公有云 SaaS，不支持私有化；Confluence Data Center 授权与运维成本高；Outline 无内置账密且强制外部 OIDC 提供商，LDAP 报错信息不明确，首次登录需手工激活。

| 画像 | 角色背景 | 典型场景 | 技术水平 | 成功标准 |

## 四、竞品分析

### 4.1 直接竞品

| 竞品 | 部署形态 | 搜索能力 | 权限模型 | AD/LDAP | 定价 | 差评暴露的核心短板 |
|------|----------|----------|----------|---------|------|--------------------|
| Confluence (Data Center / Cloud) | 本地版 / 云 | 内置搜索，仅索引 Word、PPT、Excel、PDF、HTML、纯文本 6 种附件；依赖用户打标签习惯 | 空间 + 页面级，粒度最细 | 支持，SSO 需另购 Atlassian Access（每用户每月约 5.5 美元） | 标准版每用户每月约 5.42 美元起，本地版另计 | 编辑器缓慢笨重；大页面卡顿；多栏布局导出 PDF 后排版崩坏；权限能设七八层，50 人公司直呼"没有精力搞这些"；改标题后内链不自动更新需手工修 |
| 语雀（企业版） | 仅公有云 SaaS | 差评集中区：不支持多词组合查询，跨端不支持公共搜索 | 知识库 + 目录级，深度管控弱于 Confluence | 依托阿里云/钉钉生态，无标准 LDAP 对接 | 团队专业版每人每年 99 元，旗舰版每人每年 199 元 | **不支持私有化部署，合规关过不去**；团队协作功能弱、无任务看板；数据表能力明显弱于同类；用户集中吐槽"开发速度慢"；只读不思互动，知识沉淀为死文档 |
| Wiki.js | 自托管（Node.js + PostgreSQL） | PostgreSQL 全文检索，可外接 Elasticsearch / Algolia | RBAC + 路径规则 + 页面规则，粒度较好 | 原生支持 LDAP / SAML / OAuth2 / 2FA | 免费 AGPL-3.0 | 必须自带 PostgreSQL，部署与运维门槛高于预期；中文分词需自行改造；v2.x 开发节奏放缓、v3 长期在研；导航结构不够直观 |
| Outline | 自托管（Node.js + PostgreSQL + Redis） | pg_search 英文分词，**中文搜索默认几乎不可用**，官方 Issue 长期未解 | 集合级 + 角色（Viewer / Editor / Admin） | 支持 SAML / OIDC / LDAP，但无内置账密，必须外挂 IdP；报错信息含糊 | 开源 BSL 1.1；云版每团队每月 79 美元起 | 踩坑点密集：中文分词、本地磁盘附件容器重启即丢、实时协作依赖 Redis 配置、Nginx 未代理 WebSocket 则协作与通知全失效、文件存储必须接 S3/MinIO |

### 4.2 替代方案

| 替代方案 | 企业为什么在用 | 为什么不解决问题 |
|----------|----------------|------------------|
| SharePoint + AD 深度绑定 | 已在微软生态里，版本控制与合规强，附件存储便宜 | 界面不现代，重"文件存储"轻"知识创作"；搜索与跨部门知识沉淀远弱于专业 wiki；非 IT 部门几乎不主动写文档 |
| 企业微信 / 飞书 / 腾讯乐享自带的文档与知识库 | 零采购成本、扫码即用、和 IM 天然打通、推广阻力最小 | 文档权限体系与企业 AD/LDAP 长期割裂，离职员工权限滞留；搜索不支持权限边界过滤，存在越权召回风险；数据不落在自有服务器，难满足等保与数据主权要求 |

### 4.3 市场空白（三条，即我们的机会）

1. **中文优先的私有化搜索**。现有开源方案的中文检索要么不可用（Outline），要么要自己改分词（Wiki.js / PostgreSQL ngram）。"开箱即用的中文分词 + 代码块可搜 + 结果严格按权限过滤"是断层地带。
2. **AD 组即权限，而非 AD 组需映射**。竞品普遍把"外部身份组到内部角色"的映射留给管理员手工做。AD 组与空间权限直接绑定并自动同步成员，可消除权限滞留这一最大安全隐患。
3. **国内 IM 通知的一等公民待遇**。开源 wiki 的通知基本停留在 Slack Webhook 与通用 Webhook，企业微信与飞书机器人是二等公民。

## 五、我们的差异化定位

不追求成为 Confluence 的全功能替代品。**在"内网、AD 域、中文"这三个约束下做到最顺手**：搜得准、权限不用配、装得起来、发给对的人。放弃 Jira 生态、放弃 all-in-one、放弃语义理解。

> **两条必须写进用户故事的形态约束**（与架构实现一致，避免期望落空）：
> 1. 编辑器是 **Markdown 源码编辑 + 实时预览**，不是所见即所得块编辑。画板、分栏、多维表格以 Markdown 自定义容器插入，点开弹窗编辑，**不做页面内直接拖拽排版**。
> 2. 搜索是 **字面匹配（含中文子串）**，不是语义搜索。搜"怎么申请服务器"不会命中标题为"服务器申请流程"的文档。**不对用户承诺语义理解**。

> 设计约束（违反即退回）：视觉主色禁止使用紫色到粉色渐变；图标统一采用单一 SVG 图标库（架构侧已锁定 lucide-react，禁止 emoji 图标与图标字体 CDN）；文案禁止空洞占位，空状态必须写清"下一步该做什么"。

## 六、MVP 功能清单（RICE 排序）

RICE 得分 = (Reach × Impact × Confidence) / Effort。Reach 为每季度受影响用户比例（1 至 10），Impact 取 0.25 / 0.5 / 1 / 2 / 3，Effort 单位为开发人周。

**优先级判定规则**：RICE 排定实施顺序；P0 兜底条件是"用户合同明示必须具备"或"缺失则产品无法交付"。

## 八、明确不做清单

| 不做的事 | 原因 | 何时重新考虑 |
|----------|------|--------------|
| 实时多人协同编辑 | 单实例架构下需 OT/CRDT 加 WebSocket 一整套，工作量翻倍。MVP 采用**单人编辑 + 编辑锁（30 分钟占用提示）** | 出现真实的并发编辑冲突投诉且月频次超过 10 次 |
| 文档评论与 @ 提及 | 属社区互动功能，与"安静的制度库"定位不符，且需引入未读态与消息中心 | 用户明确提出知识需要讨论沉淀，而非仅单向查阅 |
| AI 语义检索与问答 | 依赖外部大模型 API，直接违反"运行时不依赖外网"；内网缺推理算力 | 客户内网已私有部署推理服务，且有明确问答工单量支撑 |
| 字段级权限 | 管理复杂度呈指数上升，与"权限不用配"的定位直接冲突 | 出现明确的合规审计条款要求 |
| PDF 导出 | 排版保真成本高，且竞品此项恰好是差评重灾区 | 出现明确的对外分发场景 |
| 移动端原生 App | 内部 wiki 以桌面写作为主，响应式浏览器够用 | 移动端访问占比连续两个月超过 30% |
| 富文本与 Markdown 双引擎并存 | 双引擎的存储与渲染一致性是长期维护陷阱 | 出现明确的非技术岗写作受阻证据 |
| 公有云 SaaS 多租户与计费 | 产品定位是内网私有化，计费是另一套商业模式 | 公司决定对外商业化售卖 |
| Jira / GitLab 双向深度集成 | 客户未使用 Atlassian 生态，需求为零 | 客户方明确要求文档与研发任务互链 |
| 多实例集群与读写分离、国产化信创全栈适配认证 | MVP 明确单实例（架构 ADR-001）；信创认证周期长且依赖指定硬件 | 并发或数据量超单机承载；客户合同出现信创合规条款 |

## 九、关键产品决策（回答架构侧提问，据此定 API 与表结构）

### 9.1 文档的"发布"语义

**采用草稿 / 已发布两态，不做保存即发布。**

| 规则 | 说明 |
|------|------|
| 新建默认状态 | `draft`，仅作者本人与超管可见 |
| 自动保存 | 编辑中定时自动保存草稿，**不生成版本号**，避免版本表被自动保存刷爆 |
| 生成版本的时机 | 仅作者显式点击"保存"或"发布"时，才写入一条 `document_versions` 并递增版本号 |
| 进入检索索引 | **仅 `published` 文档进入全文索引**；草稿不进索引，避免搜到未定稿内容 |
| 触发通知 | 仅 `draft` 转 `published` 时触发发布通知；草稿保存不触发；已发布文档再编辑保持 `published` 并触发更新通知 |
| 撤回 | 提供"转为草稿"操作，同时从索引移除 |

### 9.2 附件权限

**附件权限跟随所在文档，不做独立授权。** 理由：独立授权会制造"附件可下载但文档读不到"的越权路径，也让管理员多一套心智负担。

| 场景 | 规则 |
|------|------|
| 已插入文档的附件 | 继承该文档的读权限；有文档读权限即可下载 |
| 上传但未插入任何文档的孤立附件 | 仅上传者本人与超管可见，不参与继承 |
| 文档被删除 | 附件进入回收站且不对外提供下载；随文档恢复一并恢复 |
| 文档权限变更 | 附件鉴权在下载接口实时按文档当前权限校验，**不做快照**；画板与数据表同样跟随，不单独授权 |

### 9.3 通知事件清单与默认开关

| 事件 | 触发条件 | 默认 | 说明 |
|------|----------|------|------|
| `document.published` | 文档由草稿转为已发布 | **开** | 订阅该文档或其所属空间的用户收到 |
| `document.updated` | 已发布文档内容被更新 | **关** | 默认关闭，避免高频编辑造成通知轰炸；由用户自行在文档级订阅 |
| `document.deleted` | 文档被删除或移入回收站 | **开** | 仅通知有该文档管理权限的用户 |
| `permission.granted` | 某用户或某组被授予新的访问权限 | **开** | 通知被授权方，是"我不知道有这个空间"的主要解法 |
| `import.finished` | Word / Excel 导入任务完成或失败 | **开** | 仅通知发起导入的人 |
| `document.moved` / `space.created` | 文档移动、新空间创建 | 关 | 低频低价值，默认关闭 |

补充规则：通知去重按"事件类型 + 目标对象 + 用户"在 5 分钟内合并一次；发送失败进重试队列并落 `notification_logs`；每通道在后台提供"测试发送"按钮，返回明确错误而非静默失败。

## 十、关键业务流程（主链路）

**创建 -> 编辑 -> 发布 -> 授权 -> 检索 -> 通知**

1. **创建**：作者在某空间点击新建，在当前父节点下创建 `draft` 文档，继承父节点的权限条目，草稿仅作者可见。
2. **编辑**：作者在 Markdown 源码编辑器写入正文，插入代码块、图片附件、内部文档链接、画板或分栏块；定时自动保存草稿但不生成版本；若他人正在编辑同一文档，进入者看到只读提示与"接管编辑"选项（编辑锁，30 分钟占用提示）。
3. **发布**：作者点击发布，校验标题非空且所属空间有效，状态由 `draft` 转为 `published`，写入一条版本记录，触发索引增量更新（标题、正文、代码块三类字段分别按分词规则入索引），并投递 `document.published` 事件。
4. **授权**：空间管理员在授权面板选择 AD 组 / 用户 / 全体登录用户，授予读、写或管理三级之一，权限沿文档树向下继承，个别文档可设例外且例外不向子孙扩散；AD 组成员变更由定时同步作业按"标记 - 清理"收敛，员工移出组后立即失去对应访问权（**这是消除权限滞留的关键回路**）；同步作业失败时保留上一次成功快照并告警，不做悲观清空。
5. **检索**：用户输入关键词，按与写入侧同一份分词实现解析查询；在索引层同时施加可见域过滤（先按用户权限集合连接，再召回）；按字段加权相关度排序（标题权重高于正文，正文高于代码块），叠加轻微时间衰减；先按 AND 拼接全部词，若结果为空则自动降级为 OR 重试；返回命中片段与高亮摘要（摘要在原文上定位截取，不使用分词后文本）。**用户永远搜不到自己无权查看的文档**。
6. **通知**：上述事件投递至通知中心，按用户订阅偏好与管理端开关，选择企业微信、飞书或邮件通道发送含内网绝对链接的消息，失败进重试队列并落库。

## 十一、验收标准示例（Given / When / Then）

- Given 用户无任何空间授权，When 登录成功，Then 首页展示空状态，文案明确引导"联系空间管理员申请访问"而非展示空白区域。
- Given 搜索服务异常，When 用户搜索，Then 搜索入口降级为提示"搜索服务暂时不可用"，文档浏览与编辑不受影响。
- Given 上传超过 50MB 或扩展名不在白名单内的附件，When 点击保存，Then 前端在上传前拦截并提示具体原因，不产生无效请求。
- Given LDAP 服务器不可达，When 用户提交域账号登录，Then 8 秒内返回可读错误，本地超级管理员账号通道兜底，不允许系统进入全员锁死状态。
- Given 两名管理员同时修改同一空间的写权限，When 后提交者保存，Then 系统提示权限已被他人变更并展示当前值，由用户确认覆盖。
- Given 断网环境，When 打开画板与代码高亮页面，Then 画板字体与代码着色均正常（证明零外网依赖）。

## 十二、非功能需求

| 类别 | 要求 | 优先级 |
|------|------|--------|
| 性能 | 首屏加载 < 3s；检索接口 p95 < 500ms（1 万篇文档量级）；文档保存 p95 < 800ms | P0 |
| 可用性 | 索引与通知可独立故障降级，核心阅读与编辑链路不受影响；提供在线热备与每日备份保留 7 天 | P1 |
| 安全 | 会话令牌签名而非明文落地；所有输入服务端二次校验；登录与检索接口速率限制；附件下载鉴权与强制下载头；密钥加密存储 | P0 |
| 兼容性 | Chrome / Edge / Firefox 最新两个大版本；企业微信内置浏览器 | P0 |
| 离线与内网 | 运行时零外网请求；字体、图标、画板资源、JS 库全部本地托管，禁止任何 CDN 引用 | P0 |

## 十三、数据埋点（内网自建轻量方案，数据不出内网）

| 事件类别 | 必埋事件 | 说明 |
|----------|----------|------|
| 获客与激活 | `session_start`、`sign_in_complete`、`first_doc_published` | 登录渠道分布（AD / SSO / 本地），以及"第一篇文档发出去"的激活率 |
| 核心使用 | `search_performed`、`search_result_clicked`、`doc_viewed`、`attachment_uploaded` | **搜索零结果率与首位点击率是判断"搜得到"是否达成的核心指标** |
| 留存与通知 | `session_duration`、`notification_sent`、`notification_failed` | 使用频次 DAU/MAU；分通道送达率与失败原因 |
| 异常 | `error_occurred` | 前端异常与 API 状态码异常，含接口名不含请求体 |

**实现要求**：前端封装 `trackEvent(event, props)`；事件名采用 `对象_动作` 命名；每个事件附带 `user_id`（内部标识，非域账号明文）、`timestamp`、`client`、`version`；不采集 IP、不存储用户正文内容。搜索词用于零结果率统计时只落聚合计数，不落原始明文。

## 十四、PM 视角的风险与建议

| 风险 | 影响 | 建议 |
|------|------|------|
| **中文分词是成败单点**，若沿用数据库默认分词将重蹈 Outline 覆辙 | 核心卖点直接失效 | 架构侧已用 bigram 预分词实测通过。建议交付前用客户真实文档做一次命中率实测，并把"写端与查询端共用一份分词实现"作为不可绕过的硬约束 |
| **迁移是隐性刚需**：首批文档从哪来决定第一天有没有人用 | 空 wiki 上线即冷启动失败 | Word/Excel 导入（P0 第 11 项）与首批约 100 篇存量文档迁移同步进行 |
| **多维表格 RICE 仅 0.25 但架构侧已排期** | 高投入低验证，挤占核心打磨时间 | 建议作为第二迭代独立验收单元，第一迭代先交付只读表格渲染 |
| **搜索是字面匹配，用户可能期待语义** | 期望落差导致"搜不到"的投诉 | 已在第五节写入形态约束。建议搜索框占位文案用"搜索文档标题、正文、代码"，不要写"问任何问题" |
| **AD 同步作业是权限安全的单点** | 失败会造成权限滞留或大面积失权 | 建议失败时保留上一次成功快照并告警，不做悲观清空——清空导致的大面积失权比滞留更糟。通知按 9.3 分级默认开关，更新类事件默认关闭以避轰炸 |
